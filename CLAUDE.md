# CLAUDE.md

Quick orientation for Claude Code sessions on this repo. Read this before exploring.

## What this is

**LLopster** is an AI-augmented SRE agent: AlertManager fires → FastAPI webhook → tiered LLM pipeline (Haiku **triage** → Sonnet **investigation** picks likely files → Opus **synthesis** sees only those files + collected Loki logs/Prom metrics) → unified-diff patch committed to a new branch → PR opened on the *right* repo → Slack notification with PR link delivered. It's source-available under the Functional Source License (FSL-1.1-ALv2 — see [LICENSE.md](LICENSE.md)); a free Community tier self-hosts with no key, and a runtime license key unlocks paid features via [src/agent/license.py](src/agent/license.py). Current code is single-tenant local dev.

See [README.md](README.md) for setup, [docs/PRODUCTION.md](docs/PRODUCTION.md) for the Helm/BYO deployment, [CONTRIBUTING.md](CONTRIBUTING.md) for the dev workflow, and [SECURITY.md](SECURITY.md) for the security model.

## Deployment shape (important)

LLopster installs as its own Helm release and connects to the cluster's **existing** Prometheus + Loki (BYO mode: `prometheus.bundled=false` / `loki.bundled=false`), or bundles them for eval. The apps LLopster monitors are **not** in its chart — each is its own repo + chart + release + GitHub PR target, with a shared observability stack (kube-prometheus-stack + Loki + Grafana Alloy). This multi-repo/BYO structure is what the reference testbed demonstrates (2 example services, 8 seeded bugs).

**Runtime topology — how the pieces fit together:**

```
demo-app / order-service ──(ServiceMonitor)──► Prometheus ┐
   │                       (apps also self-push logs)      │  (monitoring ns)
   └──(pod logs via Alloy)──────────────────► Loki ────────┤
                                                            │
Prometheus rules fire ─► AlertManager ──(llopster_managed="true")──► LLopster /webhook (llopster ns)
                                                            │
LLopster (BYO mode) reads ◄─ Prometheus + Loki query APIs in the monitoring ns
LLopster opens a PR ──► the alerting service's OWN repo
```

- **LLopster runs in BYO mode against the testbed:** `prometheus.bundled=false` + `prometheus.url=…`, `loki.bundled=false` + `loki.url=…` pointing at the `monitoring` namespace. Bundled mode (subcharts on) exists only for standalone eval.
- **Which repo a PR lands in** is driven by `agent.servicesConfig` (alert `service` label → `github_repo`) + `agent.codebases` (init-container clones each repo into `/codebases/<name>`). Both live in `helm-chart/values.dev.yaml`.
- **Values layering (LLopster chart):** `values.yaml` (generic defaults, `bundled=true`) ← `values.dev.yaml` (dev cluster: BYO URLs, storage classes, hosts, `servicesConfig`) ← `values.secret.yaml` (gitignored creds). `push-images.sh` auto-layers all three.

## Architecture (1-minute tour)

- [src/api/main.py](src/api/main.py) — FastAPI app. Lifespan builds the SQLAlchemy engine + sessionmaker (calls `init_schema`), shared `httpx.AsyncClient`, `ServiceRegistry`, `ContextCollector`, `PatchGenerator`, the notifier (`build_notifier` → Slack/Teams/none), and `GitHubClient` (each `None` if its env vars are absent — missing vars disable the feature with a warning, never a crash). The `/webhook` endpoint is non-blocking: it inserts a `Run` row per alert, fires `asyncio.create_task(process_alert(...))`, and returns the run IDs immediately. Background tasks are tracked in `app.state.background_tasks` to avoid asyncio GC. Also exposes `GET /metrics` — a DB-backed Prometheus exposition ([metrics.py](src/api/metrics.py): runs-by-status, backlog depth, trailing-day spend, cost-breaker state; computed at scrape time so it survives restarts) — scraped via the opt-in `agent.serviceMonitor`.
- [src/agent/processor.py](src/agent/processor.py) — `process_alert(run_id, alert, ...)` is the shared per-alert pipeline used by the webhook and the manual-trigger UI. Stages, in order: pre-filter ([alert_filter.py](src/agent/alert_filter.py)) → **cost circuit breaker** ([cost_breaker.py](src/agent/cost_breaker.py); skipped for operator-initiated runs via `enforce_cost_breaker=False`) → duplicate-PR dedup (`duplicate-pending-pr` by alert fingerprint) → **post-firing backoff** ([dedup.py](src/agent/dedup.py) `find_recent_unproductive_run`) → `processing_mode` check (`manual` parks at `queued`) → Haiku triage ([triage.py](src/agent/triage.py)) → context collection → Sonnet investigation ([investigator.py](src/agent/investigator.py)) → Opus synthesis ([patch_generator.py](src/agent/patch_generator.py)) → PR (path-gated to `affected_files` + validated, draft by default) → notify (Slack/Teams/none). Advances `processing_status` through pending → collecting → generating → posting → done (or `queued`/`skipped`/`failed`). Each LLM stage is settings-table kill-switchable and fails safe. Commits at every phase boundary so a crash leaves observable state. Never raises (fire-and-forget contract).
- [src/agent/triage.py](src/agent/triage.py) — cheap Haiku pre-flight classifier. Gets `{alertname, severity, summary, description, labels, annotations, service-known hint}` only (no Loki/Prom/codebase), returns `{proceed | skip, confidence 1-5, reasoning}`. Skip short-circuits the pipeline (zero collection/Opus cost). Safety belts: `severity=critical` bypasses; low-confidence skips fall through to proceed; `triage_enabled=false` disables; API failure fails-open. The system prompt distinguishes the alerting pipeline's own watchdog (skip) from an app's internal heartbeat going stale (proceed — it's a real incident).
- [src/agent/investigator.py](src/agent/investigator.py) — Sonnet step after collection. Reads alert + logs + metrics + a codebase *outline* (paths + line counts, no contents) and returns a root-cause hypothesis + ≤20 affected-files list. Triage reasoning is forwarded in. Affected-files parser validates against the real codebase root and drops hallucinated paths. Kill switch `investigation_enabled`; model override `investigation_model`.
- [src/db/](src/db/) — SQLAlchemy 2.0 async persistence. `models.py` defines `Run` (one row per alert; alert metadata, collected context, LLM response + usage, PR/Slack outcomes, lifecycle status, operator label) and `Setting` (key-value table driving runtime overrides — confidence threshold, alert filter ignore list, retention days, license-key override, etc.). `engine.py` builds the async engine + sessionmaker. `repository.py` exposes write helpers (`create_run_from_alert`, `record_collected_context`, `record_llm_response`, `record_pr`, `record_notification`, `update_status`, `set_operator_label`) and read helpers (`list_runs`, `count_runs`, `get_run`).
- [src/dashboard/runs_api.py](src/dashboard/runs_api.py) — JSON endpoints that drive the UI: `GET /api/runs` (paginated, filterable; returns `RunSummary` — no heavy fields) and `GET /api/runs/{id}` (full `RunDetail` including `alert_payload_json`, `log_lines_json`, `metric_samples_json`, full `llm_response_text`).
- [src/dashboard/web_routes.py](src/dashboard/web_routes.py) — HTML dashboard routes. `GET /` redirects to `/runs`. `/runs` is the list view; `/runs/{id}` the detail view. `/runs/partial` + `/runs/{id}/partial` are HTMX poll targets that re-render every 2s while any non-terminal status remains; once all statuses are terminal the `hx-trigger` attribute is omitted and polling stops on its own. `POST /runs/{id}/label` records the operator "correct/wrong/partial" verdict.
- [src/dashboard/templating.py](src/dashboard/templating.py) — Jinja2 environment with custom filters (`markdown` via `markdown-it-py`, `diff` via Pygments `DiffLexer`, `dt`, `duration`) and globals (`status_class`, `severity_class`, `confidence_class`, `parse_reasoning`, `is_terminal_status`). The dashboard ships zero JS frameworks and no build step (HTMX from CDN, ~30KB).
- [src/agent/alert_handler.py](src/agent/alert_handler.py) — parses AlertManager payload → `ParsedAlert`.
- [src/agent/context_collector.py](src/agent/context_collector.py) — given a `ParsedAlert`, builds LogQL (tries labels: service → app → container → pod → namespace → job) and extracts PromQL from `generatorURL`'s `g0.expr`. Errors are recorded on `AlertContext`, never raised — partial context is fine.
- [src/agent/patch_generator.py](src/agent/patch_generator.py) — the Opus **synthesis** step. `generate()` accepts the `Investigation` and `_load_codebase(only_files=…)` ships only Sonnet's flagged files (skips `__pycache__`, `.git`, `.venv`, `node_modules`, `dist`, `build`; filters by extension). Three-rung fallback to the full tree: no investigation, empty `affected_files`, or all flagged files missing on disk. Two content blocks: codebase first with `cache_control: ephemeral`, alert context (+ narrowing handoff, only when narrowing fired) second/volatile. `synthesis_used_narrowed_context` recorded per run. Uses `thinking={"type": "adaptive"}`.
- [src/integrations/notifier.py](src/integrations/notifier.py) — **notification provider seam** (same shape as `llm_provider.py`). `build_notifier(config, http)` returns a `SlackClient | TeamsClient | None` based on `NOTIFIER_PROVIDER` (`slack` default | `teams` | `none`); both clients expose the same `post_patch(alert, proposal, pr_url)` + `provider` attr, so the processor calls one without branching. `None` (provider=none, or the active provider's webhook URL unset) → notification skipped, exactly like an unset `SLACK_WEBHOOK_URL` today.
- [src/integrations/slack_client.py](src/integrations/slack_client.py) — posts Block Kit to a Slack incoming webhook (`SLACK_WEBHOOK_URL`). `build_blocks()` renders the `## Root Cause / ## Proposed Patch / ## Reasoning` sections with severity emoji, a token-usage footer, and a "View Pull Request" button when `pr_url` is set.
- [src/integrations/teams_client.py](src/integrations/teams_client.py) — posts an **Adaptive Card** to a Microsoft Teams Power Automate **Workflows** webhook (`TEAMS_WEBHOOK_URL`), wrapping it in the `{"type":"message","attachments":[…]}` envelope. Renders the same content as the Slack builder. Section parsing shared with Slack via [proposal_sections.py](src/integrations/proposal_sections.py).
- [src/integrations/github_client.py](src/integrations/github_client.py) — opens PRs via the GitHub Contents API. `proposal_has_patch()` gates the call. `open_pr()` flow: **path gates** (hard-deny `.github/`/CI/`Dockerfile`/chart-template paths + optional `affected_files` allowlist — `ProtectedPathError`, before any network call) → get default branch SHA → **fetch + apply every file in memory** (drifted hunks relocate via `_locate_hunk`) → **independent validation gate** (`validate_patched_files` — `py_compile`/YAML/JSON parse of the patched content; `PatchValidationError` on failure) → create branch (`llopster/{alertname}-{timestamp}`) → commit → open PR (**draft by default**, `draft=False` to opt out). Diff parsing is in `_parse_file_patches()` + `_apply_patch()` — pure Python hunk algorithm that **fails closed**. Requires `GITHUB_TOKEN` and a per-service `github_repo`.
- [src/integrations/loki_client.py](src/integrations/loki_client.py), [src/integrations/prometheus_client.py](src/integrations/prometheus_client.py) — thin async clients. Note shapes: `LogLine(timestamp, line, labels)`, `MetricSample(metric: dict, value: float, timestamp)`.
- [src/services_registry.py](src/services_registry.py) — loads `config/services.yaml` into `{service_name: ServiceConfig(codebase_path, github_repo)}`. Bad/missing entries log a warning and are skipped — never crashes the registry. Path is configurable via `SERVICES_CONFIG`.
- [config/services.yaml](config/services.yaml) — service-to-repo mapping. Add an entry per service the agent should handle. Alerts for unmapped services are skipped (no global fallback).
- [src/config.py](src/config.py) — env-driven `Config` dataclass. Key vars: `SERVICES_CONFIG` (default `config/services.yaml`), `LLM_PROVIDER` (`anthropic` default | `bedrock`), `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, the Bedrock trio `AWS_REGION` / `BEDROCK_MODEL` / `BEDROCK_TRIAGE_MODEL` / `BEDROCK_INVESTIGATION_MODEL` (+ optional static `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_SESSION_TOKEN`), `NOTIFIER_PROVIDER` (`slack` default | `teams` | `none`), `SLACK_WEBHOOK_URL`, `TEAMS_WEBHOOK_URL`, `GITHUB_TOKEN`, `PATCH_CONFIDENCE_THRESHOLD` (default 4), `LLOPSTER_LICENSE_KEY` (signed license JWT; empty = Community), `LLOPSTER_API_TOKEN` (inbound-auth shared secret; empty = auth disabled), `OPEN_PRS_AS_DRAFT` (default `true`), the cost-breaker ceilings `MAX_RUNS_PER_HOUR` (default **50**) / `MAX_USD_PER_DAY` (default **25**) — non-zero so there's an out-of-the-box spend cap; set a ceiling to `0` to disable it — and `PATCH_BACKOFF_MINUTES` (default 60). Exposes `llm_configured` (provider-aware: API key present, or provider=bedrock) and `notifier_configured` (active notifier's webhook URL present).
- [src/agent/llm_provider.py](src/agent/llm_provider.py) — **LLM provider seam**. One factory (`build_message_client`) returns an `AsyncAnthropic` (direct API) *or* `AsyncAnthropicBedrock` (AWS Bedrock) depending on `LLM_PROVIDER`; both expose the identical `.messages.create(...)` surface, so `Triage`/`Investigator`/`PatchGenerator` don't branch on provider — main.py builds the client via the factory and injects it (each class keeps its `api_key` fallback so tests are unchanged). `resolve_models(config)` returns the per-stage model IDs for the active provider (Bedrock uses inference-profile IDs like `us.anthropic.claude-opus-4-7-v1:0`); `effective_extended_cache_ttl(config)` forces the 1h-TTL beta **off** for Bedrock. Bedrock creds resolve via the boto3 chain (IRSA) or optional static `AWS_*` keys.
- [src/agent/license.py](src/agent/license.py) — **license-key framework**: the single paid-feature gate. `is_feature_enabled("multi_cluster")` reads an **Ed25519-signed JWT** (verified locally/offline against the embedded `PUBLIC_KEY_PEM`) describing `{tier, features, exp, clusters}`. Missing/expired/bad-signature **all fail safe** to the embedded Community license (grants nothing) — never raises. Active key resolves **override → env**: the `license_key` Setting (dashboard-pasted) wins over the `LLOPSTER_LICENSE_KEY` env var (mounted from a Secret). One image/chart for every tier; the key unlocks features at runtime. The **private** signing key is gitignored (`.license-signing-key.pem`) and is never committed — only the public half is in the repo.
- [src/agent/entitlements.py](src/agent/entitlements.py) — premium-pack entitlement seam. `is_pack_enabled(pack_id)` routes through `license.is_feature_enabled("pack:<id>")`, with a legacy `LLOPSTER_PACK_TOKEN` env allow-list kept as a pre-license fallback. Packs are optional content the loader consumes from `LLOPSTER_PACKS_DIR` (default `/packs`), failing open to the baked-in Community prompts.
- [src/api/license_api.py](src/api/license_api.py) — agent-owned `GET /api/license/status` (returns decoded status only, **never** the raw JWT) + `refresh_active_license()`, which applies the `license_key` Setting override at startup and on every status fetch (this is what makes a dashboard-pasted key reach the agent without a restart — agent and dashboard are separate pods sharing one DB). The dashboard's Settings → License card proxies this endpoint.
- [src/api/auth.py](src/api/auth.py) — **inbound-surface authentication**: one shared-secret FastAPI dependency (`require_inbound_auth`) guarding every write surface that spends money or holds the GitHub PAT (`/webhook`, trigger routes, dashboard settings/license/dispatch mutations) **and** the dashboard's read surface (`/runs`, `/diagnostics`, `/stats`, `GET /api/runs*` return raw prod logs, diffs, and full LLM output). Secret resolves **override → env**: an `api_auth_token` Setting wins over `LLOPSTER_API_TOKEN`. **Fail-safe: no secret configured = auth DISABLED** (loud startup warning) so local eval works; a secret configured = `401` (constant-time compare) before the route body runs. Accepts `Authorization: Bearer <token>` **or** HTTP Basic. **Set-once bootstrap — read the gotcha below before enabling.**
- [src/agent/cost_breaker.py](src/agent/cost_breaker.py) — **automatic cost circuit breaker**. `check_cost_breaker()` trips when runs-created/hour (`max_runs_per_hour`) or estimated synthesis spend/day (`max_usd_per_day`) reaches a ceiling; the processor then flips `processing_mode=manual` and short-circuits the current run before any LLM call. Both ceilings ship **non-zero by default** (50 runs/hr, $25/day; `0` disables a ceiling; settings-override → env). Fails safe — a breaker error logs and does NOT trip.
- [demo-app/](demo-app/) (in-repo copy, for `docker compose` local dev only) — single container, **5 independent buggy checks in parallel**, pushing logs to Loki + Prometheus metrics on `:8001`. This is the local-dev mirror of the monitored example service the agent opens PRs against; the cluster runs the sibling-repo version. Prometheus rule annotation keys must be valid identifiers (`llopster_likely_files`, not `llopster.io/...`).
  - [check_helm_values.py](demo-app/check_helm_values.py) — bad memory unit `"512MBz"` → `demo_app_config_errors_total` → `HelmValuesMisconfigured`
  - [check_db_pool.py](demo-app/check_db_pool.py) — `MAX_CONNECTIONS = 2` for 5 concurrent queries → `demo_app_db_pool_exhausted_total` → `DatabasePoolExhausted`
  - [check_cache.py](demo-app/check_cache.py) — `now + TTL_SECONDS / 1000` (s vs ms) → low hit rate → `CacheHitRateLow`
  - [check_upstream.py](demo-app/check_upstream.py) — `TIMEOUT_SECONDS = 0.001` (s vs ms) → `demo_app_upstream_timeout_total` → `UpstreamTimeoutSpike`
  - [check_scheduler.py](demo-app/check_scheduler.py) — `HEARTBEAT_INTERVAL_SECONDS = 86400` (day vs minute) → `demo_app_heartbeat_age_seconds` → `HeartbeatStale`
  - Per-scenario fixtures live in [tests/fixtures/](tests/fixtures/). Fire any of them by swapping the path in the curl recipe below.

## Conventions and gotchas

- **Python entry**: use `.venv/bin/python` and `.venv/bin/pip`. Plain `python` is not on PATH; `python3` lacks pytest.
- **Tests**: `.venv/bin/python -m pytest tests/` — all passing. `pyproject.toml` sets `pythonpath = ["."]` and `asyncio_mode = "auto"`. DB tests use `sqlite+aiosqlite:///:memory:` with `Base.metadata.create_all` per-test — fast, isolated. Tests use `httpx.MockTransport` for HTTP clients and `unittest.mock.AsyncMock` for the Anthropic client — no live API calls.
- **Schema migrations**: Alembic is wired into `init_schema` in [src/db/engine.py](src/db/engine.py) with three-way detection on startup: (a) fresh DB → `create_all` + `stamp head`, (b) legacy pre-alembic DB → `upgrade head`, (c) alembic-managed DB → `upgrade head`. New migrations go in `alembic/versions/`. Don't edit `init_schema` to skip alembic — the legacy-upgrade path keeps existing volumes from breaking when a column is added to `Run`.
- **Pre-pipeline alert filter**: [src/agent/alert_filter.py](src/agent/alert_filter.py) runs at the top of `process_alert` BEFORE Loki/Prom collection, so noise alerts cost zero outbound HTTP. Default ignore set is tiny (`AlwaysFiringDemoAlert`, `PrometheusTargetDown`, `Watchdog`, `InfoInhibitor`); operators extend via the `ignore_alertnames` setting.
- **Run retention pruner**: [src/agent/run_pruner.py](src/agent/run_pruner.py) is a long-lived asyncio task in the lifespan. On each tick (default 1h) it reads `run_retention_days` (settings-table override → env; default 90), deletes older rows, and stamps `last_pruned_at`. `run_retention_days <= 0` disables pruning.
- **Logging gotcha**: alembic's default `env.py` calls `logging.config.fileConfig(...)` which would silently reset the root logger to WARNING and wipe our `basicConfig`. Our `alembic/env.py` deliberately omits that call; `main.py`'s `basicConfig(force=True)` plus `PYTHONUNBUFFERED=1` in the Dockerfile keep `docker compose logs agent` honest.
- **Anthropic SDK**: pinned to `0.69.0` (with the `[bedrock]` extra → boto3/botocore baked into the one image). Always use model `claude-opus-4-7` with `thinking={"type": "adaptive"}` — do not pass `budget_tokens` or sampling params (they 400 on Opus 4.7).
- **LLM provider (Anthropic API vs Bedrock)**: never construct `AsyncAnthropic` directly in a new call site — go through [llm_provider.py](src/agent/llm_provider.py)'s `build_message_client` + `resolve_models` so Bedrock works. Bedrock quirks the seam handles for you: model IDs are inference-profile IDs (not the bare `claude-*` names), the `extended-cache-ttl` beta is forced off, and [cost.py](src/agent/cost.py) `pricing_for()` substring-matches the Bedrock ID back to the canonical pricing key. `LLM_PROVIDER=bedrock` in the Helm chart also creates/annotates the agent ServiceAccount for IRSA — see `agent.llm` in [values.yaml](helm-chart/values.yaml).
- **Prompt caching**: the stable codebase blob is the cache prefix. Anything that varies (timestamps, alert ID) must come AFTER the last `cache_control` marker. Verify with `usage.cache_read_input_tokens`.
- **Docker networking**: the agent is a compose service (`agent`). AlertManager reaches it as `http://agent:8000/webhook` over the compose network. `LOKI_URL`/`PROMETHEUS_URL` are overridden in compose to `http://loki:3100` / `http://prometheus:9090`. `services.yaml` and `./demo-app` are bind-mounted into `/app/`, but a `docker compose restart agent` is required if you edit `src/` (image baked).
- **Loki version**: 3.1.1. Do not re-add `metric_aggregation_enabled` to [config/loki/loki-config.yaml](config/loki/loki-config.yaml) — it 400s.
- **Helm chart is BYO-decoupled**: `prometheus`/`loki` are optional subcharts gated by `prometheus.bundled` / `loki.bundled`. The agent's `PROMETHEUS_URL` / `LOKI_URL` are *derived* in [templates/llopster-agent.yaml](helm-chart/templates/llopster-agent.yaml) (bundled svc DNS when `bundled: true`, the `.url` value otherwise — `required` errors if BYO and no URL), **not** set in `agent.env`. Even in BYO mode the subchart tarballs must be fetched (`bootstrap-helm.sh`). Three chart facts: (1) the agent/dashboard **image tag defaults to `.Chart.AppVersion`**; (2) **Postgres values are Bitnami-shaped** — the template reads `postgresql.primary.persistence.*` / `postgresql.primary.resources`; (3) the secure-render gate (top of [templates/llopster-agent.yaml](helm-chart/templates/llopster-agent.yaml)) refuses to render when a surface is exposed (Ingress enabled OR a Service of type `LoadBalancer`/`NodePort`) with no `LLOPSTER_API_TOKEN` — override with `agent.allowUnauthenticated=true`.
- **License key & paid-feature gating**: every paid feature gates through `license.is_feature_enabled(...)`. The signing is asymmetric — only the *public* key is embedded ([src/agent/license.py](src/agent/license.py) `PUBLIC_KEY_PEM`); the *private* key is gitignored and never committed. **Tests never need the real key** — they generate ephemeral keypairs and inject the public key via `monkeypatch.setattr(license, "PUBLIC_KEY_PEM", ...)`. The cardinal rule: any bad/missing/expired key must degrade to Community — a bug here should fail toward *less* access, never a crash.
- **PrometheusRule annotation/label keys must be valid Prometheus identifiers** (`^[a-zA-Z_][a-zA-Z0-9_]*$`) — **no dots or slashes**. The operator's `prometheusrulevalidate` admission webhook rejects the rule otherwise. Use `llopster_likely_files` / `llopster_runbook` (not `llopster.io/...`).
- **Webhook fixture**: [tests/fixtures/sample-alert.json](tests/fixtures/sample-alert.json) `generatorURL` must use a URL-encoded valid PromQL expression (e.g. `g0.expr=vector%281%29`), never literal `...`. Always inject the current timestamp when firing manually — the lookback window is 30 min: `jq --arg ts "$(date -u +%Y-%m-%dT%H:%M:%S.000Z)" '.alerts[0].startsAt = $ts'`
- **GitHub diff application fails closed + is path-gated + validated**: `_apply_patch` ([github_client.py](src/integrations/github_client.py)) anchors each hunk by its context/removal content via `_locate_hunk`: an exact header applies unchanged, a drifted-but-matching hunk *relocates*, and a hunk whose anchor matches nowhere raises `PatchApplyError`. Two more gates run in `open_pr` before any branch/commit: (1) **path gates** — hard-deny of execution/deploy surfaces (`.github/`, CI configs, `Dockerfile`, `docker-compose*`, chart templates) plus an optional `affected_files` allowlist, both raising `ProtectedPathError`; (2) an **independent validation gate** (`validate_patched_files` in [patch_validator.py](src/agent/patch_validator.py)) that `py_compile`s `.py` and parses `.yaml`/`.json` of the *patched* content. All are subclasses of `PatchApplyError`, so any failure aborts with **no branch, no commit, no PR** and the processor records the run `failed`. Adversarial coverage in `test_github_client.py` + `test_patch_validator.py`.
- **Inbound auth & the set-once bootstrap (gotcha)**: the shared-secret check ([src/api/auth.py](src/api/auth.py)) is **off by default** — empty `LLOPSTER_API_TOKEN` *and* no `api_auth_token` Setting means every inbound surface is **unauthenticated** (loud startup warning; fine for local eval, not for anything exposed). The chicken-and-egg: the `POST /settings/api-token` route that *sets* the token is itself auth-protected, so the bootstrap order is — **set the token once while auth is still disabled** → it immediately enforces → every later change requires the current token. Recovery if lost: set/replace `LLOPSTER_API_TOKEN` deploy-side (Secret) and clear the DB override. **Both pods must agree on the value** (the dashboard forwards the bearer on its server-side proxy calls), and AlertManager must send it as a bearer token.
- **PR draft default + cost circuit breaker**: opened PRs default to **draft** (`OPEN_PRS_AS_DRAFT=true`; opt out per-deploy via env or per-runtime via the `open_prs_as_draft` Setting) — least-privilege, human-merges. The cost breaker is checked at the **top of `process_alert`, before any LLM call**. A complementary **post-firing backoff** ([dedup.py](src/agent/dedup.py) `find_recent_unproductive_run`, `patch_backoff_minutes` default 60) suppresses re-firings whose last real run finished without a PR. Operator-initiated runs pass `enforce_cost_breaker=False` so a tripped agent can still be drained by hand.

## How to run end-to-end

```bash
.venv/bin/pip install -r requirements.txt    # for tests; the agent runs in docker
# .env needs: ANTHROPIC_API_KEY, SLACK_WEBHOOK_URL (or NOTIFIER_PROVIDER=teams + TEAMS_WEBHOOK_URL), GITHUB_TOKEN
docker compose up -d --build                  # --build needed when src/ or demo-app/ changes

# Fire a test alert with current timestamp
curl -s -X POST http://localhost:8000/webhook \
  -H "Content-Type: application/json" \
  -d "$(jq --arg ts "$(date -u +%Y-%m-%dT%H:%M:%S.000Z)" \
       '.alerts[0].startsAt = $ts' \
       tests/fixtures/sample-alert.json)" | jq
```

For active dev on the agent itself: `docker compose stop agent && .venv/bin/uvicorn src.api.main:app --reload --port 8000`. AlertManager won't reach a host-bound uvicorn (it's wired to `agent:8000` inside the compose network), but manual `curl` to `localhost:8000/webhook` still works for fixture-driven testing.

The webhook returns immediately with `{received, alerts:[{run_id, status: pending}]}`. Watch the outcome on the dashboard at `http://localhost:3001/runs/{id}` (or `curl http://localhost:3001/api/runs/{id}`): success looks like `log_lines > 0`, a confidence at or above threshold, `slack_notified: true`, and a non-null `pr_url`, plus a Slack message with a PR button and a new branch + PR in the target repo.

## Working preferences

- Iterate phase-by-phase: build → run it locally → confirm before the next phase. Don't bundle multiple phases without check-ins.
- Keep changes incremental. Don't refactor speculatively or add config knobs that aren't being used.
- Agent (`:8000`) and dashboard (`:3001`) are **separate processes/pods sharing one DB** — the dashboard survives an agent crash-loop. Remember which routes live where: `/webhook`, `/health`, `/trigger` on the agent; `/runs`, `/api/runs*`, `/stats`, `/diagnostics`, `/settings` on the dashboard.
